# 科创板每日情报雷达（kcb-radar）

每日自动采集 **科创板 619 家公司**（688 段，含未盈利上市 -U/-W）的公开信息，
产出**每日简报**、**Web 看板**和**带联网检索的 CFO 问答**。

- 数据日期范围：科创板全市场（46 个行业），**不是某一家公司**
- 数据来源：东方财富（行情 push2 / F10 财务 / 研报中心 / 公告 / 7×24 快讯），无凭证依赖
- 线上实例：<http://47.117.38.243>（完全公开，只读；写接口需令牌）

---

## 它能做什么

| 能力 | 说明 |
|---|---|
| **每日采集** | 619 家逐家拉财务摘要、行情、估值分位、研报、公告、要闻，约 90 秒 |
| **每日简报** | 确定性基线简报（所有数字来自采集数据，无模型推断），可发布到飞书知识库 |
| **Web 看板** | 今日要闻总结 / 高信号公司 / 板块焦点 / 券商观点 / 估值 / 财务 / 全量数据 |
| **CFO 问答** | 自然语言提问 → 组装「项目背景 + 当日上下文 + 编号证据」→ 模型作答，**证据可回查** |
| **联网检索** | 竞对/最新动向这类问题会走真实网络搜索，结果按 `[W编号]` 与本地 `[E编号]` 分开引用 |

### 问答的两个设计要点

1. **上下文裁剪**：数据集是 5MB 级别，不能整个塞给模型 —— 只给结构化切片
   （当日概览 + 检索命中的条目 + 相关公司的财务估值）。
2. **可信度边界写进提示词**：模型不知道"iFinD 额度耗尽所以一致预期取不到"、
   "卖方观点分三层（原文 / 摘要 / 仅元数据）"。不写清楚，它会把"没有"当成"没有这回事"，
   或者拿元数据当研报原文引用。

## 快速开始

### 部署到自己的服务器（推荐）

```bash
# 1) 构建发布包（不含密钥、数据、日志）
node scripts/build_release.cjs
#    → out/radar-release-<日期>.tar.gz

# 2) 传到服务器并执行
scp out/radar-release-*.tar.gz root@<服务器IP>:/tmp/
ssh root@<服务器IP> 'cd /tmp && tar -xzf radar-release-*.tar.gz && cd radar-release/deploy && sudo bash deploy.sh'

# 3) 在服务器上填密钥（只写服务器，不回传）
nano /etc/radar/radar.env     # 至少填 RADAR_LLM_API_KEY
systemctl restart radar
```

一键脚本会做这些事：

- 装 Node.js 20（**官方二进制包，发行版无关**）
- 建专用用户 `radar`，代码放 `/opt/radar`，数据放 `/var/lib/radar`
- systemd 常驻看板服务（崩溃自启）
- systemd timer：**每天 07:30 自动采集**、**每 15 分钟健康探活自愈**
- 可选 nginx 反代（80 → 7788，带 gzip）

详见 [`deploy/README-部署.md`](deploy/README-部署.md)。

### 本地跑

```bash
node scripts/run_collect.cjs          # 采集
node scripts/build_brief.cjs          # 生成简报
node scripts/server.js                # 起看板（默认 127.0.0.1:7788）
```

局域网访问：设 `RADAR_HOST=0.0.0.0` 后重启。看板顶栏会实时显示当前可访问的地址。

### 配置

全部配置在 `data/radar.env`（**不进版本库**）：

| 变量 | 必填 | 说明 |
|---|---|---|
| `RADAR_LLM_BASE_URL` / `RADAR_LLM_API_KEY` / `RADAR_LLM_MODEL` | 问答功能必填 | OpenAI 兼容接口。默认 `deepseek-flash` |
| `RADAR_LLM_THINKING` | | `off`（默认）/ `on`。**推理模型开推理容易把 max_tokens 烧光导致正文被截断** |
| `RADAR_LLM_MAX_TOKENS` | | 默认 8000 |
| `RADAR_SEARCH_PROVIDER` | | 默认 `auto`（自动降级），也可用 `tavily`/`brave`/`serpapi`（需 key）/ `duckduckgo`/`so360`（免 key） |
| `RADAR_ASK_RPM` / `RADAR_ASK_SEARCH_RPM` | | 问答/搜索限流（每 IP 每分钟） |
| `RADAR_ASK_DAILY_CAP` | | 问答全局日限，公网开放时建议保留（默认 300） |
| `RADAR_WRITE_TOKEN` | | 写接口（采集）令牌，非回环来源必须带 `X-Radar-Token` |


## 设计取舍

**为什么主口径全走东方财富 HTTP**：采集主口径不依赖任何凭证，
因此部署到任意服务器都能自己采。iFinD 只作补充口径，取不到时**自动降级并写进简报的披露项**，
不影响主口径 —— 这是 2026-10-23 那次「2,000 次永久额度被烧光」之后定下的路线。

**为什么问答要有独立的 W/E 两套编号**：本地数据（E）是**我们采过的、可回查的**；
网络来源（W）是**外部网页、未经本地核验**。混在一起引用，读者就分不清哪条可信。
提示词里写死：W 编号必须带来源站点和日期，与本地冲突时以本地为准，
且"检索没搜到"只能说"本次检索未覆盖"，不能说"不存在"。

**为什么公开接口也要有限流**：公网开放时每个问题都消耗模型与搜索额度。
每 IP 限流挡不住多 IP 一起刷，所以再加一道**全局日限**（默认 300 次/天），
把最坏情况钉死。

## 数据与免责

- 所有数据均来自**公开渠道**（东方财富等），本项目只做**采集、整理、检索与呈现**，
  不提供投资建议、目标价预测或买卖判断。
- 估值分位由历史估值序列自算（名义近 3 年窗口；部分标的实际历史不足 3 年，简报中会标注）。
- 同一份数据在本地与云端各自独立采集，采集时刻不同会有细微差异。
